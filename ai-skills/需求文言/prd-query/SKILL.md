# 语音需求查询

用飞书电子表格核对语音助手产品需求。命中触发词后，先确认项目和检索参数，再查表输出，不要凭记忆答。

前置：先读 [`../lark-shared/SKILL.md`](../lark-shared/SKILL.md)。读表用 `lark-cli sheets`，身份 `--as user`，scope `sheets:spreadsheet:read`。缺授权按 lark-shared 走 device login，先给 verification_url 和二维码，等用户说已授权后再续。

## 触发词

命中任一条就启用本技能。所有含字母的触发词都忽略大小写；所有含 `d01` 的触发词同时支持 `do1`；有空格同样生效：

- 对比下d01需求定义 / 对比下do1需求定义
- 对比下kp31需求定义
- 对比下d01需求 / 对比下do1需求
- 对比下kp31需求
- 对比下d01定义 / 对比下do1定义
- 对比下kp31定义
- 查下kp31需求
- d01需求查询 / do1需求查询
- kp31需求查询

不要用 `需求查询` / `查需求` / `确认需求` / `查PRD`。
`d01需求查询` / `do1需求查询` 查 D01；`kp31需求查询` 查 KP31。

## 触发后先确认输入条件

同一条消息里拆出项目和检索参数，能确认就直接查，不要再问：

1. **项目**
   - 触发词或正文含 `d01` / `do1`（忽略大小写），或命中 `d01需求查询` / `do1需求查询` → D01
   - 含 `kp31`（忽略大小写），或命中 `kp31需求查询` → KP31
   - 两个都有 → 两份都查，结论分开写
   - 都没有：cwd 在 `d01/` 用 D01，在 `kp31/` 用 KP31；仍无法判断才问一句
2. **检索参数**
   - 支持 `功能名称`、`句式说法`。写了哪个用哪个，两个都写就两个都查
   - `功能名称：打开歌词` → 按三级功能 / 讯飞功能名称搜
   - `句式说法：打开歌词` → 按说法句式搜
   - 没标参数名时，检索词同时当功能名称和句式说法搜
   - 去掉触发词和项目名，剩下的就是检索词
   - 本句没有检索词 → 用最近一轮对话里的功能或句式
   - 还是没有 → 只问缺的检索内容，不要问已经确认的项目

确认完立刻查表并按模版输出。

## 怎么查

先搜原文，没命中再搜核心词，不要按同义句扩一堆词。

1. `+cells-search --url <文档> --sheet-id <表> --find "<检索词>" --as user`
2. 按参数收窄命中：
   - `功能名称`：只保留三级功能 / 讯飞功能名称列的命中
   - `句式说法`：只保留说法句式列的命中
   - 两个都给了：两条查询结果按行去重合并
   - 没标参数名：功能名称列和说法句式列的命中都保留
3. 命中后 `+csv-get` 读该行附近，至少覆盖功能名、说法句式、语义（`service` / `semantic` / `operation` / slots）。空调表常见：`A:P`、`BA:BI`
4. 默认表没命中、内容明显属于其他域 → 换对应子表再搜
5. 仍没有 → 输出「需求表未写」，不要补造需求

只读。不要改表、不要写备注，除非用户另外要求。

## 怎么答

结论只输出功能、句式、语义。不要写 `D01需求` / `KP31需求` 项目头，不要写表格行号，不要写子表名，不要写执行逻辑、动作、提示语、版本计划。没有就写「需求表未写」。

命中几条就输出几条，按表内顺序用标号排列：`**1. 功能：<功能名>**`、`**2. 功能：<功能名>**`。功能名用三级功能 / 讯飞功能名称。不要用 markdown 有序列表 `1.`。每条只保留功能、句式、语义三块，条与条空一行。语义只列有效字段，等号前后加空格。字段用表格原文，示例值不要照抄。两份都查时先 D01 再 KP31。

模版：

**1. 功能：打开歌词**
- 句式：打开歌词 / 我要看歌词 / 显示歌词
- 语义：service = musicX，operation = INSTRUCTION，insType = OPEN_LYRIC

**2. 功能：打开歌词投屏**
- 句式：打开歌词投屏 / 把歌词投屏到仪表 / 在仪表显示歌词
- 语义：service = cmd，operation = INSTRUCTION，content = 歌词，insType = OPEN_INSTRUMENT_SHOW_CONTENT
