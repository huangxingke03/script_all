# 填写提交记录

只填这四项，用于 Gerrit / git 提交说明。已有上下文或 diff 时直接写，不要再确认。不要 invent 标题、链接、影响范围等其它字段，除非用户明确要求整份提交说明。

## 输出格式

必须恰好四行，每行以标题开头，标题后直接接正文，**不要**加冒号 `：`。四个标题各自换行，禁止拼成一段：

```text
【原因分析】一句话。
【解决方案】一句话。
【自测用例】一句话。
【自测方法】一句话。
```

硬约束：

- **按标题换行**：`【原因分析】`、`【解决方案】`、`【自测用例】`、`【自测方法】` 各占一行；正文跟在同行标题后；段与段之间用真实换行，不要空行、不要拼成一段
- 每一项只写 **一句**，句末用中文句号 `。`
- 尽量精简，沿用当前仓库近期提交的语气和粒度，不要写成多条编号列表
- 交付时用 text 代码块包住这四行，保证复制后仍分行；代码块内不要空行、不要其它说明；代码块外不要重复同一份正文

## 输入纠偏

用户贴进来若四段挤在同一段/同一行，例如：

```text
【原因分析】……。【解决方案】……。【自测用例】……。【自测方法】……。
```

先按四个标题切开，再按上面四行格式输出；不要原样回传混写文本。

标题顺序固定：原因分析 → 解决方案 → 自测用例 → 自测方法。缺哪段就先问，不要猜补。

纠偏示例：

输入（混写）：

```text
【原因分析】D01P国际右舵未唤醒态在浅色状态栏仍按白天带背景切形态，浅色页偶现显示背景。【解决方案】右舵未唤醒态固定无背景并按状态栏切字色，展示时刷新形态，布局去掉默认背景，唤醒态背景逻辑不变。【自测用例】国际右舵未唤醒在浅色/深色页面切换，确认tip无背景且字色正确，唤醒后背景与退唤醒回tip正常。【自测方法】国际右舵未唤醒在浅色/深色页面切换，确认tip无背景且字色正确，唤醒后背景与退唤醒回tip正常。
```

输出（按标题分行）：

```text
【原因分析】D01P国际右舵未唤醒态在浅色状态栏仍按白天带背景切形态，浅色页偶现显示背景。
【解决方案】右舵未唤醒态固定无背景并按状态栏切字色，展示时刷新形态，布局去掉默认背景，唤醒态背景逻辑不变。
【自测用例】国际右舵未唤醒在浅色/深色页面切换，确认tip无背景且字色正确，唤醒后背景与退唤醒回tip正常。
【自测方法】国际右舵未唤醒在浅色/深色页面切换，确认tip无背景且字色正确，唤醒后背景与退唤醒回tip正常。
```

## 怎么写

依据当前对话里的问题结论、代码改动、缺陷标题来写：

| 字段 | 写什么 |
|------|--------|
| 原因分析 | 问题是什么 / 为什么会出现（常对应“未做 X”“误判 Y”“逻辑遗漏”） |
| 解决方案 | 实际改了什么（常与标题或修复动作同向，一句说完） |
| 自测用例 | 在什么场景下看什么结果（验证点一句说完） |
| 自测方法 | 怎么验证（常见可与自测用例同句或极相近，不要展开步骤条） |

风格对齐近期 KP31 / D01 提交，例如：

```text
【原因分析】国内版语音设置二级页面主驾全时免唤醒/多人同时对话/大模型对话，未移除beta标记。
【解决方案】国内版语音设置二级页面主驾全时免唤醒/多人同时对话/大模型对话，移除beta标记。
【自测用例】国内版语音设置二级页面主驾全时免唤醒/多人同时对话/大模型对话，确认是否还有beta标记。
【自测方法】国内版语音设置二级页面主驾全时免唤醒/多人同时对话/大模型对话，确认是否还有beta标记。
```

信息不够就先问缺什么，不要猜关键根因。

## 默认行为

1. 默认只输出上述四行（包在 text 代码块里），交给用户复制。
2. 用户说写入 / 更新现有提交说明时：只改 HEAD 提交说明里这四行，其它字段原样保留；未明确要求 commit / amend 时不要改 git。
3. 用户只要其中几项时，只填要求的项，仍保持每项独占一行。

## 回复

成功后只给按标题分行的四行正文（text 代码块）。不要再解释写法，不要附整份 commit message，除非用户要完整提交说明。
